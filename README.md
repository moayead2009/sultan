# Solutions Gate Website

Bilingual English/Arabic corporate website and structured CMS for Solutions Gate, implemented from the approved V2 planning package. The public site, CMS, publication gates, SEO, accessibility, responsive behavior and source-confirmation rules from Phases 1–3 are preserved; Phase 4 adds production-readiness and handoff tooling without deploying the application.

## Stack and runtime

- Next.js 16 App Router, React 19 and TypeScript.
- PostgreSQL 16+ with Prisma migrations.
- NextAuth credentials authentication with Argon2 passwords, OWNER/ADMIN authorization and server-revocable sessions.
- Local filesystem media storage or S3-compatible object storage; this deployment may use a persistent local uploads directory.
- Optional Resend inquiry notification after database persistence.
- English and Arabic public content with true RTL behavior for Arabic.

## Repository map

`app/` contains public routes, CMS routes, API handlers and operational probes. `components/` contains public/CMS UI. `lib/` contains auth, publication, storage, SEO, inquiry, security and runtime primitives. `prisma/` contains the relational schema, migrations and deterministic seed. `scripts/` contains owner bootstrap, production preflight and database backup/restore tooling. `docs/` contains architecture, operations, handoff, decisions, history, section contracts and source-asset provenance.

## Local setup

Use Node.js 24 LTS (24.x) and PostgreSQL 16+. Copy `.env.example` to `.env`, set a local `DATABASE_URL` and a long `AUTH_SECRET`, then run:

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
OWNER_NAME='Owner' OWNER_EMAIL='owner@example.test' OWNER_PASSWORD='use-a-strong-local-password' npm run bootstrap:owner
npm run dev
```

The deterministic site root uses `SiteSettings.defaultLocale`, with Arabic as the planning default. CMS routes are under `/admin`. There is no public registration.

## Production preparation

Do not place real secrets in the repository. Configure the real production environment in the deployment platform, run `npm run ops:preflight`, take a verified database backup, apply `npm run db:migrate`, build with `npm run build`, and validate `/api/health` plus `/api/ready` before traffic is switched. Production media may use `STORAGE_DRIVER=local` with an explicit persistent `LOCAL_UPLOAD_DIR`, or `STORAGE_DRIVER=s3` with a configured bucket and public URL.

The first OWNER is created with the one-time `OWNER_NAME`, `OWNER_EMAIL` and `OWNER_PASSWORD` process documented in `docs/operations.md`. Remove those bootstrap inputs immediately after use.

## CMS and publishing

Editors manage bilingual pages, sections, navigation/footer, services, projects, clients, capabilities, metrics, leadership, contact data, media, SEO, redirects and inquiries in `/admin`. English and Arabic content is authored independently; translation records are not generated by machine fallback. Publication validation must pass before public rendering. Draft preview remains authenticated and noindex.

Redirect records execute at the request boundary and protected/admin/preview/API surfaces remain excluded. Inquiry submissions are sanitized and persisted before optional notification; status and retention settings remain CMS-controlled.

## Source-confirmation safety

Unconfirmed metrics, clients, project facts, legal copy, contact email/address/social accounts, the unresolved English premium capability tier name and other owner-confirmation items remain gated or unpublished. Do not publish them without owner confirmation.

## Operations and handoff

Read `docs/architecture.md` for the application/data design, `docs/operations.md` for production environment, deployment, migrations, backup/restore, monitoring and rollback, and `docs/handoff.md` for the final ownership checklist and known limitations. `docs/decisions.md` and `docs/history.md` are the implementation decision and change records.

## Verification

The required verification path is the pull-request CI workflow targeting `main` (feature-branch pushes do not run a duplicate full workflow): clean install, high-severity dependency audit, Prisma generation, fresh migration and seed, production-preflight contract, shell safety checks, lint, typecheck, unit/integration tests, Playwright E2E, accessibility/responsive/browser matrix, production build, readiness/liveness checks and performance budgets. Phase 4 is not a deployment authorization; merge and deployment remain explicit owner actions.
